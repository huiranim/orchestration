## 2. 전제 조건 확인

### Java
```bash
java -version
# openjdk version "21.0.10" 2026-01-20 (Homebrew)
```

JAVA_HOME 미설정 상태 확인 → 수동 설정 필요.

**이슈**: `/usr/libexec/java_home -v 21` 실패 — Homebrew Java는 macOS 기본 탐색기에 자동 등록되지 않음.  
**해결**: Homebrew 경로 직접 지정.

```bash
export JAVA_HOME=$(brew --prefix openjdk@21)
echo 'export JAVA_HOME=$(brew --prefix openjdk@21)' >> ~/.zshrc
```

**주의**: `brew --prefix openjdk`는 최신 버전(25)을 가리킴. 반드시 `openjdk@21`로 명시.

### Python
```bash
# macOS에서 python 명령어 없음 → python3 사용
python3 --version
```

## 3. Airflow 환경 구성

### venv 생성
```bash
cd orchestration/airflow/
python3 -m venv .venv && source .venv/bin/activate
# (.venv) 프롬프트 확인
```

### 패키지 설치
```bash
pip install apache-airflow==2.10.4 pyspark pytest \
  --constraint "https://raw.githubusercontent.com/apache/airflow/constraints-2.10.4/constraints-3.11.txt"
```

### 환경변수 영속화
`.venv/bin/activate` 하단에 다음 export 추가 (venv 활성화 시마다 자동 적용):
```bash
export AIRFLOW_HOME="$(dirname "$VIRTUAL_ENV")/.airflow"
export AIRFLOW__CORE__DAGS_FOLDER="$(dirname "$VIRTUAL_ENV")/dags"
export AIRFLOW__SCHEDULER__DAG_DIR_LIST_INTERVAL=10
export PYTHONPATH="$(dirname "$VIRTUAL_ENV")/macos_shims:$PYTHONPATH"  # 아래 SIGSEGV 이슈 참고
export AIRFLOW__CORE__LOAD_EXAMPLES=False  # 예제 DAG 69개 미로드 (적용 후 airflow db reset 필요)
```

### 이슈: macOS gunicorn 워커 SIGSEGV (중요)

**증상**: `airflow standalone` 실행 시 webserver/triggerer 워커가 `Worker (pid:...) was sent SIGSEGV!`를 초당 수백 건 출력하며 무한 재시작. UI 접속 불가.

**디버깅 과정**:
1. 스케줄러는 멀쩡하고 gunicorn 기반 컴포넌트(webserver, triggerer)만 죽음 → fork 관련 의심
2. macOS 크래시 리포트(`~/Library/Logs/DiagnosticReports/Python-*.ips`)의 faulting thread 스택 분석:
   ```
   libsystem_trace.dylib   _os_log_preferences_refresh   ← 크래시 지점
   CoreFoundation          _CFBundleLoadExecutableAndReturnError
   _setproctitle...so      darwin_set_process_title
   ```

**근본 원인**: gunicorn이 워커를 `fork()`한 뒤 각 워커가 `setproctitle` C 확장으로 프로세스명을 변경. 이 라이브러리의 darwin 구현이 fork 직후 CoreFoundation을 호출하는데, CoreFoundation은 fork-safe하지 않아 SIGSEGV 발생. (`OBJC_DISABLE_INITIALIZE_FORK_SAFETY=YES`는 ObjC 런타임의 fork *abort*만 억제하므로 이 하드 segfault에는 무효)

**해결**: `setproctitle`은 `ps` 출력상 프로세스명 표시용 cosmetic 기능이라 오케스트레이션 동작에 영향 없음. 동일 이름의 no-op 모듈(`airflow/macos_shims/setproctitle.py`)을 만들어 `PYTHONPATH`로 site-packages보다 앞에 두어 C 확장을 shadow. 모든 import 구문은 그대로 동작.

**한계/주의**: 정석 해결책은 아님(macOS 전용 우회). 표준 대안은 Docker Compose로 Airflow를 Linux 컨테이너에서 실행하는 것. 이 과제는 학습 목적이라 셰임으로 standalone을 유지하기로 결정.

**검증**: 셰임 적용 후 `curl http://localhost:8080/health` → HTTP 200, SIGSEGV 0건. webserver/scheduler/triggerer/gunicorn(워커 4개) 모두 정상.

### UI 접속 확인
`http://localhost:8080` 접속 → admin 로그인. 임시 패스워드는 `.airflow/standalone_admin_password.txt`에 저장됨.
